# 웹 UI (Docker)

브라우저에서 지원 현황·공고·서류를 관리하고, `/setup`·`/apply`·`/interview` 같은 Claude Code 명령을 대화창에서 실행합니다.

## 실행

```bash
cp env.example .env        # 저장소 루트에서
# .env에 둘 중 하나 입력
#   CLAUDE_CODE_OAUTH_TOKEN=...   (Pro/Max 구독: 호스트에서 `claude setup-token` 실행 후 붙여넣기)
#   ANTHROPIC_API_KEY=...         (API 키, 사용량 과금)
docker compose up -d --build
```

Linux에서는 저장소 폴더를 쓸 수 있도록 내 계정 ID로 이미지를 빌드하세요: `APP_UID=$(id -u) APP_GID=$(id -g) docker compose up -d --build` (macOS의 Docker Desktop은 필요 없음). ID를 바꿔 다시 빌드해도, 컨테이너가 시작할 때 Claude 설정 볼륨의 소유자를 새 ID로 넘겨주므로 기존 대화 기록과 인증 정보가 그대로 유지됩니다.

http://localhost:3000 을 엽니다. 포트는 `.env`의 `WEB_PORT`로 바꿀 수 있습니다.

처음 열면 홈에 **"이 작업 폴더를 신뢰할까요?"** 카드가 뜹니다(설정 화면에도 있습니다). Claude Code는 신뢰하지 않은 폴더에서 `.claude/settings.json`의 허용 목록을 무시하므로, 누르지 않으면 검색 도구나 PDF 검사도 매번 승인해야 합니다. 누르면 웹 UI가 이 저장소의 허용·거부 규칙을 직접 적용합니다. 동의는 웹 UI 전용 파일(`ai-job-search-web.json`, Docker에서는 `claude-config` 볼륨 안)에만 기록되고 Claude Code 설정 파일은 바꾸지 않습니다.

## API 엔드포인트 바꾸기 (base URL)

Claude Code가 Anthropic API 대신 다른 Anthropic 호환 서버(LLM 게이트웨이, 프록시, 회사 중계 서버)로 요청을 보내게 하려면 `.env`에 넣고 `docker compose up -d`를 다시 실행하세요.

```bash
ANTHROPIC_BASE_URL=https://gateway.example.com     # 이 PC에서 도는 서버면 http://host.docker.internal:<포트>
ANTHROPIC_AUTH_TOKEN=...                           # 게이트웨이가 Bearer 토큰을 쓰면 (API 키를 쓰면 ANTHROPIC_API_KEY)
ANTHROPIC_MODEL=...                                # 게이트웨이의 모델 이름이 다를 때만
```

- 컨테이너 안에서 `localhost`는 컨테이너 자신입니다. 이 PC의 프록시는 `host.docker.internal`로 접근합니다(Linux에서도 되도록 `compose.yaml`에 설정해 두었습니다).
- 설정 화면의 "AI 서버" 카드에 현재 주소가 표시됩니다(주소에 들어 있는 계정 정보와 쿼리는 지우고 보여 줍니다).
- 이 서버로 프로필, 공고, 생성한 서류 내용이 모두 전송됩니다. 신뢰하는 서버만 쓰세요.

## 개인정보 저장 위치

`/setup`은 프로필을 `documents/profile/`(git 제외)에 씁니다. 추적되는 프레임워크 파일은 플레이스홀더만 유지하므로 공개 fork에 커밋해도 개인정보가 올라가지 않습니다. 규칙은 `CLAUDE.md`의 "Personal Data Storage"에 있습니다.

개인 파일(프로필, `documents/`, 지원 기록, 생성한 CV·커버레터)은 별도 비공개 git 기록으로 백업합니다.

```bash
tools/private_data.sh save "메모"      # 스냅샷 (변경이 없으면 아무것도 안 함)
tools/private_data.sh log              # 기록 보기
tools/private_data.sh remote <비공개 저장소 URL> && tools/private_data.sh push --confirm-private
# 공개 GitHub 저장소로는 push를 거부합니다. 비공개 여부는 익명으로 확인할 수 없어서 --confirm-private가 필요합니다.
```

- 저장소 폴더 전체가 컨테이너의 `/workspace`에 마운트됩니다. 프로필, 지원서, PDF는 모두 호스트 폴더에 그대로 저장됩니다.
- Claude 대화 기록은 Docker 볼륨 `claude-config`에 남습니다. `docker compose down -v`를 하면 지워집니다.
- 이미지에는 Bun, Python(pypdf), Typst, Noto CJK 폰트, poppler가 들어 있습니다. LaTeX는 없으니 Typst 템플릿(`kr-resume`, `kr-letter`)을 쓰세요.

## 화면

| 메뉴 | 내용 |
|---|---|
| 홈 | 새 공고 지원(URL/본문 → `/apply`), 내 지원 요약·마감 임박, 추천 공고, 자주 쓰는 작업. 설정에 문제가 있을 때만 안내 한 줄 |
| 공고 찾기 | `/scrape`·`/rank` 결과 (`job_scraper/seen_jobs.json`), 제외 사유, 공고별 지원서 만들기 |
| 내 지원 | `job_search_tracker.csv`, 생성된 이력서/커버레터 PDF, 결과 기록·면접 준비·후속 연락 버튼 |
| 서류함 | `cv/`, `cover_letters/`, `documents/` 등 파일 보기, 종류별 업로드(`documents/` 하위 폴더) |
| 내 프로필 | 프로필 파일 보기, `/setup`·`/expand` 실행, AI에게 수정 요청 |
| AI 비서 | Claude Code 전체 대화 기록. `/`를 입력하면 기능 목록 |
| 설정 | AI 연결·서버 주소·PDF 도구·템플릿·작업 폴더 신뢰·파일 접근 상태, 데이터 초기화(프로필·대화 기록) |

버튼으로 시작한 작업은 화면을 옮기지 않고 오른쪽 **AI 작업** 패널에서 진행됩니다. 진행 단계(에이전트의 할 일 목록), 지금 하는 일, 권한 요청·질문, 결과와 만든 파일이 표시되고, AI가 답을 기다리면 어느 화면에서든 알림이 뜹니다. 권한 요청은 하려는 일을 문장으로 보여 주고 원본 입력은 "기술 정보"에 둡니다. 프로그램 실행(Bash) 요청은 명령 전문을 항상 바로 보여 줍니다.

웹 UI는 데이터를 자유롭게 고치지 않습니다. 트래커와 프로필은 지금처럼 `/apply`, `/outcome`, `/setup` 같은 명령이 관리하고, 웹은 그 명령을 실행하고 결과를 보여 줍니다. 예외는 하나, **내 지원 보드에서 단계를 옮길 때**입니다. 이때 웹은 `tools/tracker_state.py`만 거쳐 트래커를 바꿉니다. 이 도구는 `/outcome`의 규칙(정식 상태 철자, 쉼표 없는 날짜 메모, 작성됨에서 옮길 때 지원일 기록, 종료 시 서류 사본과 `outcome.md` 보관)을 그대로 따르고, 파일을 잠근 뒤 통째로 바꿔 쓰며, 화면이 본 상태와 지금 상태가 다르면 바꾸지 않습니다. 터미널의 AI가 같은 순간 트래커를 고치는 경우까지 막지는 못하니, 두 곳에서 동시에 같은 지원을 바꾸지는 마세요.

공고 카드나 홈에서 **지원서 만들기**를 누르면 AI가 중간에 묻지 않고 끝까지 진행합니다(대화창의 `/apply`는 지금처럼 물어봅니다). 시작 전에 고른 적합도 기준과 옵션이 질문에 대한 답이 되고, AI가 정한 것은 결과에 "AI가 이렇게 정했어요"로 남습니다. 공고에 수상한 지시가 있거나, 적합도가 기준보다 낮거나, 공고를 열 수 없으면 멈추고 확인을 받습니다. 작업 기록은 `.ajs/runs/`에 저장되어(깃에 올라가지 않음) 서버를 다시 켜도 남고, 멈춘 작업은 이어서 할 수 있습니다.

지원 사이트에 **자기소개서 문항**이 있으면 지원서 만들기 창에서 미리 넣거나, 지원 상세 화면의 "자기소개서 문항" 카드에 넣습니다(양식에서 복사한 문항을 한 번에 붙여넣으면 번호와 글자 수 제한을 읽어 나눠 줍니다). AI는 프로필과 그 지원서를 바탕으로 답변 글만 돌려주고, 이 작업에서는 파일 쓰기와 명령 실행이 꺼져 있습니다. 글자 수는 서버가 `tools/self_intro_count.py`로 한국 시장 가이드의 계산 방식 그대로(공백 포함·공백 제외·EUC-KR 바이트) 세어, 제한을 넘거나 85%에 못 미치는 답변만 AI에게 최대 두 번 다시 쓰게 합니다. 저장은 서버가 `tools/tracker_state.py write-self-intro`로 하며, 지원이 아직 작성됨일 때만 `documents/applications/<회사>_<직무>/self_intro.txt`에 씁니다. 같은 회사·직무의 예전 지원이 남긴 답변 파일은 덮어쓰지 않고, 그 경우 이번 답변은 [받기]로 받습니다. 지원서 만들기에서 "커버레터 대신 이 문항 답변만 내요"를 고르면 커버레터를 만들지 않고 답변 파일이 지원 기록의 커버레터 칸에 남습니다. 답변마다 복사·다시 쓰기 버튼이 있고(다시 쓰기는 그 답변만 바뀝니다), 이미 낸 지원의 답변은 보기만 할 수 있습니다.

예외는 업로드와 **설정 > 데이터 초기화**입니다. 초기화는 테스트하고 남은 데이터를 빠르게 지우기 위한 것으로, 고른 항목만 지웁니다.

- **확인 절차**: 화면이 지울 목록(프로필 항목 이름, 대화 개수)을 먼저 보여 주고, `초기화`를 입력해야 실행됩니다. 서버는 확인 문구와 함께 그 목록을 받아, 확인한 뒤로 프로필 목록이 바뀌었으면 지우지 않고 대화는 확인한 것만 지웁니다. 초기화는 한 번에 하나만 돌고, 도는 동안에는 새 AI 작업을 시작하거나 메시지를 보낼 수 없습니다.
- **내 프로필**: `documents/profile/` 안의 항목을 모두 지우고 폴더는 남깁니다(`/reset profile`의 삭제 단계와 같음). 업로드처럼 폴더를 한 단계씩 링크를 따라가지 않고 열며, 안의 링크는 링크만 지웁니다. 저장소와 `documents/profile` 사이(예: `documents` 자체)나 그 안에 마운트(바인드 마운트 포함)가 있거나 다른 장치로 넘어가면 아무것도 지우지 않습니다. 이 보장은 Linux(Docker)의 이야기입니다. macOS 기본 실행에서는 파일 접근이 막혀 동작하지 않고, `AJS_INSECURE_PATH_CHECKS=1`로 켠 경우는 경로만 보고 확인하므로 실행 중에 다른 프로그램이 폴더를 바꿔치기하는 경우까지 막지는 못합니다. AI 작업이 진행 중이거나 시작되는 중이면 프로필만 지우는 것은 거부합니다. 대화 기록도 함께 고르면 작업을 멈추고, 모든 작업 프로세스가 끝난 것을 확인한 뒤에만 지웁니다. 지우다 멈추면(하위 폴더 안에서 멈춘 경우 포함) 일부를 지웠다고 알리고 남은 항목을 보여 줍니다.
- **AI 대화 기록**: 이 웹 서버는 Claude Code 프로세스를 직접 띄워 종료를 관찰합니다. 초기화는 이 서버의 작업을 모두 멈추고 프로세스가 실제로 끝난 것을 확인한 뒤, 이 폴더의 Claude Code 대화 기록을 SDK(`deleteSession`)로 지웁니다. 같은 저장소의 다른 git worktree에서 나눈 대화는 대상이 아닙니다. 기본으로는 이 서버의 프로세스가 마지막으로 쓰고 끝난 기록만 지웁니다. 터미널에서 나눈 대화나 웹에서 멈춘 뒤 터미널에서 이어 쓴 기록은 "이 폴더로 실행 중인 Claude Code가 없어요"를 체크해야 함께 지웁니다. 실행 중인 터미널 프로그램을 멈추지는 않으니 먼저 종료하세요. 이 서버의 작업이 시간 안에 끝나지 않으면 그 대화와 프로필은 지우지 않습니다. 대화 수는 SDK가 보여 주는 대화 목록 기준입니다.
- 올린 서류, 지원 기록, 만든 이력서·커버레터는 지우지 않습니다. 예전 버전의 `/setup`이 추적되는 지침 파일에 직접 써 둔 개인정보도 건드리지 않으니, 그것까지 정리하려면 같은 카드의 "AI로 꼼꼼하게 초기화"(`/reset profile`)를 쓰세요.
- 다른 사이트에서 온 요청은 다른 API처럼 Host/Origin 검사에서 막힙니다. 확인 문구는 실수 방지 장치이지 인증이 아닙니다. 지운 프로필은 `tools/private_data.sh`로 백업해 두었다면 그 기록에서 되살릴 수 있습니다.

## 보안

- 포트는 `127.0.0.1`에만 열립니다. 이 PC 밖에서는 접속할 수 없습니다.
- 서버는 `Host`가 localhost가 아니거나 `Origin`이 다른 사이트인 요청을 거부합니다. 다른 웹사이트가 브라우저를 통해 이 서버에 명령을 보낼 수 없게 하려는 것입니다.
- Claude의 도구 권한은 `.claude/settings.json` 규칙을 그대로 따릅니다. 규칙에 없는 작업은 대화창에 허용/거부 카드로 뜹니다. "이 세션에서 항상 허용"은 그 세션에만 적용되고 설정 파일에 저장되지 않습니다.
- 파일 API는 `cv/`, `cover_letters/`, `documents/`, `reports/`, `upskill/`, `company_research/`, `templates/`와 `CLAUDE.md`, `job_search_tracker.csv`만 읽습니다. `.env`와 `.git`은 읽을 수 없습니다.

## 컨테이너 없이 실행

```bash
cd web && bun install && bun run start   # http://localhost:3000
```

호스트의 Claude Code 로그인을 그대로 씁니다. 개발 중에는 `bun run dev`로 자동 새로고침을 켤 수 있습니다. 테스트는 `bun test`, 타입 검사는 `bun run typecheck`로 실행합니다.

**macOS 등 Linux가 아닌 환경에서는 웹 UI의 파일 읽기·업로드가 기본으로 꺼집니다.** 파일 API는 저장소 밖으로 빠져나가지 못하게 폴더를 한 단계씩 열어 확인하는데, 이 방식(`/proc/self/fd`)은 Linux에만 있습니다. 다른 환경에서는 경로만 보고 확인할 수밖에 없고, 그 사이에 다른 프로그램이 폴더를 링크로 바꿔치기하면 저장소 밖 파일을 읽거나 덮어쓸 수 있습니다. 그래서 기본은 차단이고 대시보드에 안내가 뜹니다(대화창은 그대로 쓸 수 있습니다). 저장소에 쓸 수 있는 프로그램을 모두 신뢰할 때만 다음처럼 켜세요.

```bash
AJS_INSECURE_PATH_CHECKS=1 bun run start
```
