# 웹 UI UX 개편 기획

> 목표: "Claude Code 명령을 실행하는 웹 터미널"을 **"AI 비서가 대신 일해 주는 구직 관리 앱"**으로 바꾼다.
> 사용자는 명령어·파일 경로·도구 이름을 몰라도 지원서 작성부터 결과 기록까지 끝낼 수 있어야 한다.

---

## 1. 진단: 왜 터미널처럼 느껴지나

현재 코드(`web/src/client/`)를 기준으로 정리했다.

| # | 증상 | 위치 | 사용자에게 생기는 문제 |
|---|---|---|---|
| 1 | 버튼 이름이 명령어 그대로 (`/apply 실행`, `/setup 시작`, `공고 검색 (/scrape)`) | Dashboard, Profile, Jobs | 명령어를 외워야 하고 뜻을 짐작해야 함 |
| 2 | 모든 버튼이 `runCommand()` → **대화 화면으로 강제 이동** | `api.ts` `runCommand` | 보던 화면을 잃음. "지원" 하나 눌러도 채팅 로그로 튕김 |
| 3 | 작업 과정이 도구 호출 로그로 보임 (`🔧 Bash · 실행 중` + JSON `<pre>`) | `Chat.tsx` `EventList` | 지금 뭘 하는지, 얼마나 남았는지 모름. `/apply`는 6단계짜리 긴 작업인데 진행률이 없음 |
| 4 | 권한 요청이 도구 이름 + 원본 입력 JSON | `Chat.tsx` permission 카드 | 일반 사용자는 허용해도 되는지 판단할 수 없음 |
| 5 | 대시보드 첫 줄이 시스템 진단 (Claude 인증, API 엔드포인트, Typst, 템플릿) | `Dashboard.tsx` stats | 사용자 목표(지원·마감)보다 개발자 정보가 먼저 보임 |
| 6 | 안내 문구에 파일명·환경변수 (`job_search_tracker.csv`, `.env`, `documents/cv`, `AJS_INSECURE_PATH_CHECKS`) | 빈 상태, 경고 상자 전반 | 내부 구조를 알아야 이해되는 문장 |
| 7 | 영어 상태값이 그대로 노출 (공고 필터의 `ranked`, `new`), 관문 결과가 `위치 FAIL` | `Jobs.tsx` | 왜 추천에서 빠졌는지 알 수 없음 |
| 8 | 서류 화면이 폴더 탐색기 (`documents/references` 선택 → 파일 선택 → 올리기) | `Documents.tsx` | "이력서 올리기" 같은 목적 대신 경로를 골라야 함 |
| 9 | 프로필이 파일명 탭(`01-candidate-profile.md`) + 마크다운 원문, 수정은 "대화창에서 요청하거나 파일을 직접 고치세요" | `Profile.tsx` | 내 정보를 보고 고치는 화면이 없음 |
| 10 | 작업 결과가 대화 속 마크다운 텍스트, 끝에 `완료 · 312.4초 · 세션 누적 약 $1.23` | `Chat.tsx` result | 만들어진 CV·커버레터를 바로 볼 수 없고, 비용·시간이 결과보다 눈에 띔 |
| 11 | AI가 질문/승인을 기다려도 대화 목록 안의 작은 칩으로만 표시 | `Chat.tsx` 세션 목록 | 다른 화면에 있으면 몇 분씩 멈춰 있는 걸 모름 |
| 12 | 대화 제목이 입력한 프롬프트 앞 60자 (`/apply https://www.wanted.co.kr/wd/...`) | `agent.ts` title | 이전 작업을 찾기 어려움 |

**핵심 원인은 두 가지다.**
1. 화면이 **명령(도구) 중심**으로 짜여 있고 **사용자 목표**(지원하기, 결과 챙기기) 중심이 아니다.
2. AI 작업이 **대화 로그**로만 보이고, **진행 상황과 결과물**로 보이지 않는다.

## 2. 설계 원칙

1. **명령어 대신 동사.** 메인 UI에는 `/명령`, 파일 경로, 환경변수, 도구 이름을 쓰지 않는다. 필요한 사람은 "자세히"를 펼치거나 명령 팔레트를 쓴다.
2. **화면을 떠나지 않는다.** AI 작업은 오른쪽 **작업 패널(drawer)**에서 돌고, 사용자는 보던 화면에 그대로 있는다.
3. **로그 대신 진행 단계와 결과.** "Bash 실행 중"이 아니라 "2/6 이력서 초안 작성 중". 끝나면 텍스트가 아니라 **결과 카드**(PDF 미리보기, 적합도, 다음 할 일 버튼)를 보여 준다.
4. **AI가 기다리면 어디서든 알린다.** 질문과 승인 요청은 전역 배지, 탭 제목, 브라우저 알림으로 알린다.
5. **데이터는 공용 상태 도구로만 쓴다.** 웹은 자유 형식으로 파일을 고치지 않는다. 즉시 반응해야 하는 좁은 조작(지원 단계 옮기기)만 에이전트와 같은 검증 도구(`tools/tracker_state.py`)를 거쳐 직접 쓰고, 그 밖의 데이터는 계속 명령(`/apply`, `/outcome`, `/setup`)이 관리한다. (2026-11 개정: 아래 §8.2 결정에 따름)
6. **고급 기능은 숨기되 막지 않는다.** 대화창과 슬래시 명령은 "AI와 직접 대화"와 `⌘K` 팔레트로 남긴다.

## 4. 정보 구조 (IA)

```
홈 (오늘 할 일)
공고 찾기
내 지원 (파이프라인)
  └ 지원 상세
서류함
내 프로필
AI 비서 (대화)          ← 하단으로 이동, 고급 사용자용
설정                    ← 인증·엔드포인트·Typst·템플릿·신뢰·파일 접근 상태
```

전역 요소:
- **작업 패널**: 오른쪽 drawer. 진행 중인 AI 작업 목록 + 선택한 작업의 진행 상황.
- **상단 알림 배지**: "AI가 답을 기다려요 (2)". 누르면 해당 작업 패널이 열림.
- **명령 팔레트 `⌘K`**: 기능 검색 + 슬래시 명령 직접 입력.

## 5. 핵심 경험 설계

### 5.1 첫 실행 온보딩 (체크리스트형)

지금은 대시보드에 경고 상자 3~4개와 시스템 상태가 한꺼번에 뜬다. 이를 **단계형 체크리스트**로 바꾼다. 모두 끝나기 전에는 홈 맨 위에 고정한다.

```
시작하기 ●●●○○  3/5 완료
 ✓ 1. AI 연결 확인           (자동 점검. 실패할 때만 설정 방법 안내)
 ✓ 2. 이 폴더 신뢰하기        ("매번 승인하지 않아도 되도록" + [신뢰하기])
 ✓ 3. 이력서 올리기           (드래그 앤 드롭 영역, 바로 업로드)
 ▶ 4. AI가 프로필 만들기      [시작] → 작업 패널에서 질문에 답하기
   5. 희망 조건 정하기 → 첫 공고 찾기
```

- 1번 실패 시 문구 예: "AI에 연결하지 못했어요. 설치 가이드의 '인증 정보 넣기'를 따라 한 뒤 다시 시작해 주세요." 환경변수 이름은 "자세히" 안에만.
- macOS 파일 접근 차단(`fileAccess: blocked`)도 체크리스트 0번 "실행 환경"으로 넣고, 해결책을 하나만(Docker로 실행) 먼저 보여 준다.

### 5.2 작업 패널: 화면 이동 없이 AI 작업 실행

`runCommand()`의 `location.hash = #/chat/...`를 없애고, 작업 패널을 연다.

**작업 카드 구조**
```
┌ 지원서 만들기 · 토스 / 백엔드 엔지니어 ───── 진행 중 ┐
│ ① 적합도 평가        ✓  적합도 4/5                     │
│ ② 이력서·자기소개서 초안 ✓                              │
│ ③ 회사 조사·검토      ●  토스 채용 페이지 읽는 중…       │
│ ④ 피드백 반영                                           │
│ ⑤ PDF 만들기·검사                                       │
│ ⑥ 지원 기록                                             │
│                                   [중단]  [자세히 보기] │
└─────────────────────────────────────────────────────────┘
```

- **진행 단계 소스 (권장안)**: `agent.ts`의 `WEB_APPEND` 시스템 프롬프트에 "명령을 시작할 때 TodoWrite로 단계 목록을 만들고 단계마다 갱신하라"를 추가한다. TodoWrite 도구 입력은 이미 `assistant.tools`로 클라이언트에 오므로, 클라이언트에서 마지막 TodoWrite를 파싱해 체크리스트로 그리면 된다. 명령 스펙(`.claude/commands/*.md`)은 고치지 않아도 된다.
- **대비책**: TodoWrite가 없으면 도구 호출을 사람 말로 바꾼 "현재 활동" 한 줄만 보여 준다(§5.4).
- **작업 제목**: 세션 생성 시 `kind`(apply/outcome/…)와 `subject`(회사·직무)를 같이 넘겨 "지원서 만들기 · 토스 / 백엔드"로 표시한다. 지금은 프롬프트 앞 60자다.
- 전체 대화 로그는 "자세히 보기"로 들어가는 기존 Chat 화면을 그대로 쓴다.

### 5.3 AI가 기다릴 때: 질문과 승인

**질문 (AskUserQuestion)**
- 작업 패널 맨 위에 **큰 선택 버튼** 카드로 띄운다. 라디오 목록 대신 옵션 카드 + 설명.
- 다른 화면에 있으면 상단 배지, 탭 제목(`(1) 답변 필요 · AI Job Search`), 브라우저 알림(사용자가 허용한 경우)으로 알린다.

**권한 요청**
- 도구별로 사람 말 템플릿을 만든다. 원본 JSON은 "기술 정보" 접기 안에 둔다.

| 도구 | 표시 문구 | 위험도 표시 |
|---|---|---|
| WebFetch / 포털 CLI | "**{도메인}** 페이지를 읽으려고 해요" | 낮음 |
| WebSearch | "'{검색어}'를 웹에서 검색하려고 해요" | 낮음 |
| Write / Edit | "**{파일 설명}**을(를) 만들거나 고치려고 해요" (예: 이력서 초안, 지원 기록) | 보통 |
| Bash | "프로그램을 실행하려고 해요: {요약}" + 명령 원문 | 높음(주황) |

- 버튼: `허용` / `이 작업 동안 계속 허용` / `거부`. "세션"이라는 말 대신 "이 작업".
- 작업 공간을 신뢰하면 대부분 요청이 사라지므로, 요청이 3번 이상 뜨면 "폴더를 신뢰하면 이런 확인이 줄어요" 안내를 한 번 보여 준다.

### 5.4 도구 로그를 활동 설명으로

`EventList`의 `🔧 {t.name}`을 매핑 함수로 바꾼다.

| 도구·입력 패턴 | 활동 문구 |
|---|---|
| `WebFetch {url}` | "{도메인} 읽는 중" |
| `Read documents/cv/*` | "올린 이력서 읽는 중" |
| `Write cv/main_*` | "이력서 초안 작성" |
| `Write cover_letters/*` | "자기소개서 초안 작성" |
| `Bash … verify_pdf.py` | "PDF 레이아웃 검사" |
| `Bash … typst compile` | "PDF 만드는 중" |
| `Bash … rank_state.py` | "공고 점수 저장" |
| `Agent` (하위 에이전트) | "검토 담당 AI가 확인 중" |
| 그 외 | "작업 중" (원문은 자세히 안에) |

연속된 도구 호출은 한 줄 타임라인으로 묶고, 펼치면 지금의 `<pre>`를 그대로 보여 준다.

### 5.5 결과 카드

`result` 이벤트가 오면 텍스트 대신 결과 카드를 보여 준다.

- **지원서 만들기**: CV·자기소개서 PDF 썸네일(클릭하면 미리보기), 적합도, "주요 맞춤 포인트" 3줄, 버튼 `[지원 페이지 열기] [지원함으로 표시] [수정 요청]`
- **공고 찾기/평가**: "새 공고 23건 중 추천 5건" + 상위 3개 카드 + `[추천 공고 보기]`
- **결과 기록**: 바뀐 상태 칩 + 다음 할 일(면접이면 `[면접 준비]`)

결과물은 세션 중 Write 이벤트의 경로와 작업 후 다시 읽은 트래커·파일 목록으로 찾는다. 소요 시간·비용은 "자세히" 안으로 옮긴다.

### 5.6 화면별 개편

**홈 (오늘 할 일)**
- 맨 위: 온보딩 체크리스트(미완료일 때만)
- "할 일" 인박스: AI 답변 대기 → 마감 임박(D-7) → 후속 연락이 필요한 지원(지원 후 N일 무응답) → 다가오는 면접 → 새 추천 공고
- 큰 입력창 하나: "지원하고 싶은 공고 링크를 붙여넣으세요" → `[지원서 만들기]`. 본문 붙여넣기는 "링크가 안 열리나요?"로 펼치기
- 파이프라인 요약 숫자(작성 3 · 지원 7 · 면접 1)를 누르면 내 지원으로 이동
- 시스템 상태 카드 5개는 **설정**으로 옮긴다. 문제가 있을 때만 홈에 한 줄 경고

**공고 찾기**
- 탭: `추천 (n)` / `검토 필요 (n)` / `제외됨 (n)` / `전체`. 상태 select 대신 탭
- 표 대신 카드 목록: 적합도 막대(예: 82점), 회사·직무, 마감 D-day, 강점 2개·부족한 점 1개
- 제외 사유는 사람 말로: "희망 근무지와 맞지 않아요 — 판교 상주"
- 카드를 누르면 오른쪽 상세(강점·갭 전체, 원문 링크) + `[지원서 만들기]`
- `[새 공고 찾기]`는 작은 폼(분야 키워드, 넓게/좁게)으로 열고, 끝나면 "지금 평가할까요?"를 제안해 `/rank`까지 한 흐름으로 잇는다

**내 지원 (파이프라인)**
- 기본 보기는 칸반: 작성됨 → 지원함 → 면접 → 결과(오퍼/합격/불합격/무응답). 표 보기는 토글로 남긴다
- 카드: 회사, 직무, D-day, 서류 아이콘, 마지막 활동일
- **지원 상세 페이지**(`#/applications/:id`): 타임라인, CV·자기소개서 미리보기, 공고 링크, 메모, 담당자
  - `[결과 기록]` → 모달 폼(결과 선택, 날짜, 메모) → `/outcome {회사} {직무} {결과} {메모}`로 조립해 작업 패널에서 실행
  - `[면접 준비]`, `[후속 연락 메일]`도 같은 방식
- 칸반 드래그로 상태를 바꾸는 기능은 `tools/tracker_state.py`를 거쳐 바로 반영한다(§8.2 결정)

**서류함**
- 두 구역으로 나눈다
  - **내가 올린 자료**: 이력서 / 경력증명·성적 / 추천서 / 포트폴리오 / LinkedIn 각각을 드롭존 카드로. 폴더 select 제거
  - **AI가 만든 서류**: 지원 건별로 묶어 "토스 · 백엔드 — 이력서, 자기소개서"
- 경로·바이트 크기는 작게, 대신 "3일 전"처럼 상대 시간

**내 프로필**
- 파일명 탭 대신 섹션 카드: 기본 정보 / 경력 / 기술 / 학력 / 희망 조건 / 일하는 방식. 프로필 마크다운의 `##` 제목을 기준으로 나누고, HTML 주석과 플레이스홀더는 숨긴다
- 섹션마다 `[AI에게 고쳐 달라고 하기]` → 작은 입력창 → 작업 패널 실행(예: "경력 섹션: 2024년 프로젝트 추가 …")
- 희망 조건은 칩으로 보여 준다(직무, 지역, 연봉, 언어)

**AI 비서 (기존 대화)**
- 빈 화면의 명령어 안내 대신 **추천 프롬프트 칩**: "이 공고 나랑 맞아?", "자기소개서 톤 더 부드럽게", "이번 주 할 일 정리해 줘"
- `/` 자동완성은 그대로 두고, 명령 설명을 한국어 사용자 문구로 표시

## 8. 결정이 필요한 사항

1. **주 사용자**: 개발 지식이 없는 구직자인가, 본인(개발자)인가? 전자라면 3단계까지가 필수이고, 후자라면 1~2단계로도 효과가 크다.
2. **웹의 직접 쓰기 허용 여부**: 칸반 드래그로 상태 바꾸기, 공고 "관심 없음" 같은 즉시 반응형 조작은 웹이 트래커·`seen_jobs.json`을 직접 고쳐야 자연스럽다. 지금 원칙("웹은 파일을 직접 고치지 않는다")을 지킬지, `tools/` 스크립트를 거치는 좁은 쓰기 API를 열지 정해야 한다. **권장: 3단계까지는 원칙 유지(폼 → 명령), 이후 `tools/rank_state.py` 같은 기존 검증 스크립트를 호출하는 API로 제한적으로 연다.**
   - **결정 (2026-11):** 좁게 연다. 웹의 쓰기 경로는 에이전트와 공유하는 검증 도구를 거치는 것만 허용한다: 지원 단계 전환(`tools/tracker_state.py transition`, 구현됨), 공고 관심 없음(`rank_state.py dismiss`, 예정), 프로필 수정 제안 적용(예정). 각 경로는 잠금, 통째 바꿔 쓰기, 스키마 검사, 화면이 본 상태 확인을 갖춘다.
3. **진행 단계 표시 방식**: TodoWrite 지시(권장, 명령 스펙 수정 없음) vs 각 명령 스펙에 단계 마커 추가(더 정확하지만 스펙 13개 수정).
